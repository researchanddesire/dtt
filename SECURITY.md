# Security

Report suspected vulnerabilities privately to support@researchanddesire.com.
Include affected versions, a minimal reproduction, and the expected impact.
Do not post credentials, personal session data, or device identifiers in public
issues. Do not test against another person's device or live account.

Development builds use an explicitly configured local server and synthetic
identities. Production builds verify HTTPS and preserve official OTA validation.
Public verification keys identify signed artifacts; they are not secret device
credentials. Access to an official service remains subject to that service's
current authorization requirements.
